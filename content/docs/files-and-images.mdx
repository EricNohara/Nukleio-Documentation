# Files and Images

Nukleio can store the files and images your portfolio needs so you do not have to manually replace assets inside your portfolio codebase. Common uploads include portraits, resumes, transcripts, and project thumbnails.

## Supported Asset Types

The exact upload areas depend on the dashboard section you are using, but common Nukleio assets include:

| Upload Item               | Allowed File Types |
| ------------------------- | ------------------ |
| Portrait or profile image | Image              |
| Resume                    | PDF                |
| Transcript                | PDF                |
| Project thumbnails        | Image              |

All files have an upper limit of **50MB** allowed. Files over this limit must be compressed before uploading to your dashboard. All uploaded files are automatically compressed and optimized for faster load times in your connected portfolio applications.

## Uploading a File

To upload a file:

1. Open the [documents area](https://www.nukleio.com/user/documents) in the dashboard.
2. Select the upload box.
3. Drag and drop a file into the upload area, or choose Browse Files.
4. Review the preview when available.
5. Save the change.
6. Check your connected portfolio to confirm it uses the new file.

Selecting a file may show a temporary preview before the final save. Make sure you still save the form or page after choosing the file if the dashboard requires it.

## Image Uploads

Images are commonly used for profile portraits and project thumbnails.

For best results:

- use a clear image with the subject centered
- avoid tiny screenshots with unreadable text
- crop project thumbnails consistently
- use modern image formats when supported
- keep file sizes reasonable so portfolio pages load quickly

If your connected portfolio displays images in cards or grids, consistent image dimensions will usually look better.

## PDF Uploads

PDFs are commonly used for resumes and transcripts.

Before uploading a PDF:

- confirm it is the current version
- open it locally to make sure it is not corrupted
- check that your name and contact details are correct
- remove private information you do not want shared
- use a clear filename for your own organization

Your portfolio can link to these files so visitors can view or download them.

## Replacing Existing Assets

When you replace an asset in Nukleio, your portfolio should use the latest saved version once it fetches fresh data.

Common reasons to replace an asset include:

- updating a resume
- changing your profile photo
- refreshing project screenshots
- uploading a corrected transcript
- improving image quality or cropping

If the old asset still appears on your portfolio, the issue may be browser caching, deployment caching, or the portfolio frontend storing an older API response.

## File Safety

Only upload files you are comfortable using with your portfolio.

Before uploading, check that files do not include:

- private addresses you do not want public
- phone numbers you do not want public
- internal company information
- private repository screenshots
- credentials, keys, or tokens

Nukleio helps manage your portfolio assets, but you should still review file contents before making them part of a public portfolio experience.

## Upload Checklist

Before relying on an uploaded asset in your portfolio:

- [x] File is the correct version.
- [x] File opens successfully.
- [x] Image preview looks right.
- [x] PDF content is accurate.
- [x] File does not expose sensitive information.
- [x] Connected portfolio shows the new asset after refresh or rebuild.
