# Public API Reference

The Nukleio public API lets connected portfolio websites request public portfolio data for an authenticated Nukleio user. This page documents the exact behavior of the public API.

## Request Shape

The public endpoint for retrieving your nukleio portfolio data is:

```
https://www.nukleio.com/api/public/getUserData
```

Your integration should send the API key as a bearer token:

```txt
Authorization: Bearer YOUR_API_KEY
```

Portfolio frontends should handle optional or missing fields gracefully. For example, do not assume every user has a transcript, every project has a demo URL, or every social link is present.

## Error Responses

### Missing API Key

If the request does not include a bearer token, the API returns an unauthorized response.

```json
{
  "message": "Unauthorized"
}
```

### Invalid API Key Format

If the key format is invalid, the API can return:

```json
{
  "message": "Invalid API key format"
}
```

### Unauthorized Key

If the key is not recognized or is not allowed to access the requested data, the API returns:

```json
{
  "message": "Unauthorized"
}
```

### Server Error

If Nukleio cannot complete the request because of an internal issue, the API returns:

```json
{
  "message": "Internal server error"
}
```

## Status Codes

| Status | Meaning                                        |
| ------ | ---------------------------------------------- |
| `200`  | Request succeeded and returned portfolio data. |
| `204`  | CORS preflight request succeeded.              |
| `401`  | Missing, invalid, or unauthorized API key.     |
| `500`  | Nukleio could not complete the request.        |

## CORS

The public endpoint supports browser-based portfolio integrations and responds to `OPTIONS` preflight requests.

Allowed request methods include:

```txt
GET, OPTIONS
```

Allowed request headers include:

```txt
Authorization, User-Email, Content-Type, Accept, X-Target-User-Id
```

## Integration Notes

When building a portfolio integration:

- send the API key as a bearer token
- handle `401` responses by checking the key value and request header
- handle missing optional fields in the UI
- avoid assuming every array has items
- decide whether your portfolio should fetch fresh data on every request or cache it
- rotate keys if they are exposed in a public repository
