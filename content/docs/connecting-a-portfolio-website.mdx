# Connecting a Portfolio Website

After your Nukleio account has profile data, projects, files, and an API key, you can connect a portfolio website to the public API.

A connected portfolio requests your public Nukleio data, then renders that data using your own design.

## Before You Connect

Make sure you have completed these steps in Nukleio:

- profile information added
- at least one project added
- files or images uploaded if your portfolio needs them
- API key created
- API key copied and stored securely

You can connect earlier for testing, but having real content makes it easier to confirm that your portfolio is rendering data correctly.

## How the Integration Works

Your portfolio sends a request to Nukleio's public API using your API key.

```txt
GET /api/public/getUserData
Authorization: Bearer YOUR_API_KEY
```

Nukleio validates the key and returns your public portfolio data as JSON. Your frontend then maps that JSON into portfolio sections such as your hero, bio, project list, links, and file downloads.

## Where to Store the API Key

Store your API key in an environment variable when possible.

Example:

```txt
NUKLEIO_API_KEY=your_api_key_here
```

Avoid placing the key directly inside reusable components or committing it to a public repository.

If your portfolio fetches data from server-side code, keep the key server-side. If your portfolio must fetch directly from the browser, understand that the key may be visible to visitors through browser developer tools.

## Basic Request Shape

Your integration should send the API key as a bearer token:

```txt
Authorization: Bearer YOUR_API_KEY
```

If you are building with JavaScript, the request shape usually looks like this:

```js
const response = await fetch("https://YOUR_NUKLEIO_DOMAIN/api/public/getUserData", {
  headers: {
    Authorization: `Bearer ${process.env.NUKLEIO_API_KEY}`,
  },
});

if (!response.ok) {
  throw new Error("Failed to load Nukleio portfolio data");
}

const data = await response.json();
```

Replace `https://YOUR_NUKLEIO_DOMAIN` with the live Nukleio application URL provided for your account or environment.

## Rendering the Data

After fetching the data, your portfolio should map the response into your UI.

Common sections include:

- hero name, role, and bio
- profile image
- project cards
- project detail pages
- technology lists
- GitHub and LinkedIn links
- resume link
- contact section

Your portfolio controls the design. Nukleio supplies the content.

## Refreshing Content

How quickly updates appear depends on how your portfolio fetches data.

Common patterns:

| Portfolio behavior | Update timing |
| --- | --- |
| Fetches on every page load | Updates can appear after refresh. |
| Uses server-side rendering | Updates appear when the server fetches fresh data. |
| Uses static builds | Updates may require a rebuild or cache refresh. |
| Uses client-side caching | Updates appear after the cache expires or is cleared. |

If a Nukleio update does not appear immediately, check your portfolio caching strategy before assuming the update failed.

## Testing the Connection

After connecting your portfolio:

1. Load the portfolio page.
2. Confirm that profile data appears.
3. Confirm that projects render correctly.
4. Open project and social links.
5. Check uploaded files or images.
6. Make a small edit in Nukleio.
7. Refresh or rebuild the portfolio.
8. Confirm the edit appears.

## Integration Checklist

Before sharing the connected portfolio, confirm that:

- the API key is valid
- the request uses the `Authorization` bearer header
- missing optional fields do not break the UI
- project cards handle long descriptions or names
- uploaded files and images load correctly
- your portfolio handles API errors gracefully
- updated Nukleio content appears after refresh, rebuild, or cache expiration
